Chapter 8: Inheritance, MRO & Composition Over Inheritance

Subclassing can share behavior cleanly when a true is-a relationship exists, yet deep or tangled inheritance hierarchies quickly turn rigid and fragile. Mastering Python's Method Resolution Order (MRO), cooperative super() calls, and composition gives you adaptable designs without brittle coupling.

When inheritance fits: Use inheritance when a subclass genuinely specializes a base contract and preserves every invariant of the parent class for example, a specialized report formatter or a specific fee rule under a shared base type.

Why composition often wins: Wrapping focused collaborator objects inside a class lets you swap strategies or behaviors at runtime without multiplying subclasses across every combination of features.

Design Choice Mechanism / Syntax Primary Strength Defensive Pitfall to Avoid
Single Inheritance class Child(Parent): Reuses shared attributes and behavior for true subtypes Overriding base methods in ways that break parent invariants
MRO & super() ClassName.__mro__, super() Follows C3 linearization deterministically across multiple inheritance Hardcoding ParentClass.__init__(self, ...) instead of using super()
Composition Holding collaborator instances on self Keeps behaviors modular, swappable, and easy to test in isolation Exposing unvalidated internal collaborators or forwarding every method blindly
Mixin Ordering class Worker(LogMixin, Base): Adds focused capabilities without deep tree hierarchies Placing conflicting attribute names or incompatible signatures in mixins
Core Principles of Inheritance, MRO & Composition
  • Prefer composition when assembling behaviors: Favor "has-a" or "uses-a" relationships over deep "is-a" trees when combining policies like rate calculators, validators, or exporters.
  • Respect parent invariants in subclasses: Any subclass must accept valid parent inputs and keep base invariants intact rather than relaxing rules unexpectedly.
  • Inspect MRO when combining classes: Python computes a deterministic lookup order (__mro__) using C3 linearization so super() walks the chain predictably.
  • Validate composed collaborators explicitly: Check that injected helper objects implement the expected interface or callable contract before using them.

8.1 Inheritance and Preserving Base Invariants

When a subclass extends a base class, it should call super().__init__(...) so shared validation runs once and every child instance starts with guaranteed invariants.

from decimal import Decimal, InvalidOperation

class ShippingRatePolicy:
    """Base policy calculating a validated base rate from package weight in kilograms."""

    def __init__(self, base_rate: Decimal, per_kg_rate: Decimal) -> None:
        """Initialize and validate non-negative base and per-kilogram rates."""
        # Validate base rate and per-kilogram rate defensively.
        self._base_rate: Decimal = self._parse_non_negative_decimal(base_rate, "base_rate")
        self._per_kg_rate: Decimal = self._parse_non_negative_decimal(per_kg_rate, "per_kg_rate")

    @staticmethod
    def _parse_non_negative_decimal(candidate_value: object, field_label: str) -> Decimal:
        """Convert and validate a finite non-negative Decimal value."""
        # Reject booleans explicitly because bool subclasses int in Python.
        if isinstance(candidate_value, bool):
            raise TypeError(f"{field_label} cannot be a boolean.")

        # Parse Decimal or string/numeric inputs safely.
        try:
            parsed_decimal: Decimal = (
                candidate_value
                if isinstance(candidate_value, Decimal)
                else Decimal(str(candidate_value).strip())
            )
        except (InvalidOperation, TypeError) as parse_error:
            raise ValueError(f"Invalid decimal for {field_label}: {candidate_value}.") from parse_error

        # Reject NaN, Infinity, or negative rates.
        if not parsed_decimal.is_finite() or parsed_decimal < Decimal("0.00"):
            raise ValueError(f"{field_label} must be a finite non-negative Decimal.")

        return parsed_decimal

    def calculate_fee(self, weight_kg: Decimal) -> Decimal:
        """Compute shipping fee for a positive package weight in kilograms."""
        # Reject booleans and require a positive finite Decimal weight.
        if isinstance(weight_kg, bool) or not isinstance(weight_kg, Decimal):
            raise TypeError("weight_kg must be a Decimal.")

        if not weight_kg.is_finite() or weight_kg <= Decimal("0.00"):
            raise ValueError("weight_kg must be a positive finite Decimal.")

        # Return base charge plus weight-based charge.
        return self._base_rate + (self._per_kg_rate * weight_kg)

class ExpressShippingPolicy(ShippingRatePolicy):
    """Subclass adding a validated express surcharge to the base shipping fee."""

    def __init__(self, base_rate: Decimal, per_kg_rate: Decimal, express_surcharge: Decimal) -> None:
        """Initialize parent rates and validate the express surcharge."""
        # Delegate base and per-kg validation to the parent constructor.
        super().__init__(base_rate=base_rate, per_kg_rate=per_kg_rate)

        # Validate express surcharge as a non-negative finite Decimal.
        self._express_surcharge: Decimal = self._parse_non_negative_decimal(
            express_surcharge,
            "express_surcharge",
        )

    def calculate_fee(self, weight_kg: Decimal) -> Decimal:
        """Compute express shipping fee by adding the surcharge to the base fee."""
        # Compute standard fee via super() and add the validated surcharge.
        standard_fee: Decimal = super().calculate_fee(weight_kg)

        return standard_fee + self._express_surcharge

if __name__ == "__main__":
    # Compare standard and express shipping fees for a 3.5 kg parcel.
    standard_policy: ShippingRatePolicy = ShippingRatePolicy(Decimal("8.00"), Decimal("2.00"))
    express_policy: ExpressShippingPolicy = ExpressShippingPolicy(
        Decimal("8.00"),
        Decimal("2.00"),
        Decimal("15.00"),
    )

    parcel_weight: Decimal = Decimal("3.5")

    print("Standard fee:", standard_policy.calculate_fee(parcel_weight))
    print("Express fee:", express_policy.calculate_fee(parcel_weight))

8.2 Method Resolution Order (MRO) and Cooperative super()

When multiple classes participate in a hierarchy, Python orders lookup paths in __mro__. Calling super() follows that MRO list rather than jumping straight to a hardcoded class name, keeping cooperative methods in sync.

from typing import list as TypingList

class AuditTrailMixin:
    """Mixin recording formatted audit entries during a workflow step."""

    def __init__(self, audit_log: TypingList[str], **kwargs: object) -> None:
        """Initialize audit storage and forward remaining keyword arguments."""
        # Reject non-list audit log containers defensively.
        if not isinstance(audit_log, list):
            raise TypeError("audit_log must be a list.")

        # Store reference to shared audit log and continue MRO initialization.
        self._audit_log: TypingList[str] = audit_log

        super().__init__(**kwargs)

    def record_step(self, step_description: str) -> None:
        """Append a step entry and continue along the MRO chain."""
        # Reject non-string step descriptions.
        if not isinstance(step_description, str) or not step_description.strip():
            raise ValueError("step_description must be a non-empty string.")

        # Record step and pass execution to the next class in MRO.
        self._audit_log.append(f"AUDIT: {step_description.strip()}")

        super().record_step(step_description)

class BaseWorkflowRunner:
    """Base runner providing a terminal record_step implementation."""

    def __init__(self, runner_name: str) -> None:
        """Initialize runner with a non-empty name."""
        # Reject blank or non-string runner names.
        if not isinstance(runner_name, str) or not runner_name.strip():
            raise ValueError("runner_name must be a non-empty string.")

        self._runner_name: str = runner_name.strip()

    def record_step(self, step_description: str) -> None:
        """Finalize step recording at the base of the hierarchy."""
        # No-op terminal hook for cooperative super() calls.
        return None

class AuditedOrderRunner(AuditTrailMixin, BaseWorkflowRunner):
    """Combine audit logging mixin with BaseWorkflowRunner following MRO."""

# Run this block only when executing the file directly rather than importing it.
if __name__ == "__main__":
    # Inspect MRO order and run a step through the combined runner.
    collected_entries: list[str] = []

    workflow: AuditedOrderRunner = AuditedOrderRunner(
        audit_log=collected_entries,
        runner_name="nightly-dispatch",
    )

    workflow.record_step("validated order batch")

    # Display MRO class names and recorded audit entries.
    mro_names: list[str] = [cls_item.__name__ for cls_item in AuditedOrderRunner.__mro__]

    print("MRO:", mro_names)
    print("Audit log:", collected_entries)

8.3 Composition Over Inheritance for Flexible Behavior

Instead of creating separate subclasses for every combination of pricing and packaging rules, compose a focused processor around a rate policy object. You can swap policies cleanly without changing the processor's public contract.

class ParcelCheckoutService:
    """Composable service calculating parcel totals using an injected rate policy."""

    def __init__(self, rate_policy: ShippingRatePolicy) -> None:
        """Initialize checkout service with a validated ShippingRatePolicy instance."""
        # Reject objects that are not ShippingRatePolicy instances.
        if not isinstance(rate_policy, ShippingRatePolicy):
            raise TypeError("rate_policy must be a ShippingRatePolicy instance.")

        # Store composed policy collaborator on the service instance.
        self._rate_policy: ShippingRatePolicy = rate_policy

    @property
    def rate_policy(self) -> ShippingRatePolicy:
        """Return the active shipping rate policy."""
        # Expose composed policy via read-only property.
        return self._rate_policy

    def quote_shipment(self, item_subtotal: Decimal, parcel_weight_kg: Decimal) -> Decimal:
        """Calculate total charge from item subtotal plus policy-computed shipping fee."""
        # Reject booleans and validate non-negative finite item subtotal.
        if isinstance(item_subtotal, bool) or not isinstance(item_subtotal, Decimal):
            raise TypeError("item_subtotal must be a Decimal.")

        if not item_subtotal.is_finite() or item_subtotal < Decimal("0.00"):
            raise ValueError("item_subtotal must be a finite non-negative Decimal.")

        # Delegate weight validation and fee calculation to the composed policy.
        shipping_fee: Decimal = self._rate_policy.calculate_fee(parcel_weight_kg)
        return item_subtotal + shipping_fee

if __name__ == "__main__":
    # Quote the same parcel under two composed shipping policies.
    weight_kg: Decimal = Decimal("4.0")
    subtotal: Decimal = Decimal("60.00")

    standard_checkout: ParcelCheckoutService = ParcelCheckoutService(
        ShippingRatePolicy(Decimal("5.00"), Decimal("1.50"))

        ExpressShippingPolicy(Decimal("5.00"), Decimal("1.50"), Decimal("12.00"))
    )

    print("Express total:", express_checkout.quote_shipment(subtotal, weight_kg))
